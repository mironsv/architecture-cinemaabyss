# Миграция монолита CinemaAbyss в микросервисы

## Обзор монолита CinemaAbyss
 В проекте реализована следующая функциональность:

- GET  /health                          → Health check (статус сервера)

- GET  /api/users                       → Получить всех пользователей
- GET  /api/users?id=<id>               → Получить пользователя по ID
- POST /api/users                       → Создать нового пользователя

- GET  /api/movies                      → Получить все фильмы
- GET  /api/movies?id=<id>              → Получить фильм по ID
- POST /api/movies                      → Создать новый фильм

- GET  /api/payments                    → Получить все платежи
- GET  /api/payments?id=<id>            → Получить платёж по ID
- GET  /api/payments?user_id=<id>       → Получить платежи пользователя
- POST /api/payments                    → Создать новый платёж

- GET  /api/subscriptions               → Получить все подписки
- GET  /api/subscriptions?id=<id>       → Получить подписку по ID
- GET  /api/subscriptions?user_id=<id>  → Получить подписки пользователя
- POST /api/subscriptions               → Создать новую подписку

## Определим и приоритизируем компоненты, которые должны быть извлечены из монолита

### Определение и анализ компонент

Техника 1. Анализ домена бизнеса.
- Управление пользователями (управление регистрацией, аутентификацией, профилями и предпочтениями пользователей).
- Каталог фильмов (включая поиск, метаданные).
- Управление платежами (управление всем жизненным циклом заказа, включая управление корзиной, оформление заказа, обработку платежей).
- Управление подписками (управление маркетинговыми кампаниями, рекламными предложениями и скидками).
- Сервис взаимодействия с рекомендательной системой.
- Сервис интегации с сервисами лояльности, маркетплейсами.

Техника 2. Технический анализ
- код не является тесно связанным.
- отсутствует ответственность за специализированные алгоритмы и требования к обработке данных, т.к. они находятся во внешнем сервисе (рекомендательная система).

Техника 3. Анализ производительности
- масштабируемость - это цель миграции.
- Процесс оформления заказа в управлении платежами. Процесс является узким местом: время отклика в периоды пикового трафика слишком высокое.
- Функциональность поиска в каталоге фильмов. Частые жалобы пользователей на медленную и зачастую нерелевантную выдачу результатов указывают на необходимость оптимизации этого компонента.

### Приоритезация методом MoSCoW

Must (обязательно)
- Управление платежами (влияет на продажи и удовлетворённость клиентов).
- Каталог фильмов (точное и эффективное управление каталогом товаров необходимо для обслуживания клиентов и осуществления продаж).
- Аутентификация и авторизация

Should (нужно)
- Управление пользователями.
- Сервис интеграции с сервисами лояльности, маркетплейсами (новый функционал)

Could (желательно)
- Сервис взаимодействия с рекомендательной системой.
- Управление подписками.
